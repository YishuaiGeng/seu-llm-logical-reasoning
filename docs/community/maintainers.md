# 维护手册

本页面向组内负责维护知识库的成员，说明日常维护中的常见操作。内容写作规范见[贡献指南](../../CONTRIBUTING.md)，技术结构与发布方式见[维护与发布](maintenance.md)。

## 角色与职责

| 角色 | 职责 |
| --- | --- |
| 知识库负责人 | 管理仓库设置与成员权限，确定栏目结构与发布版本，处理行为准则与安全问题。 |
| 备份维护者 | 具有与负责人相同的仓库权限，在负责人不在时审阅合并、处理紧急问题。 |
| 栏目维护人 | 分别关注逻辑基础、推理方法、训练与验证、评测分析等主题，审阅对应内容，维护候选论文清单。 |
| 轮值记录人 | 每次组会按轮值整理公开记录，会后请汇报人确认技术内容。 |
| 全体成员 | 撰写与修订内容，互相审阅 PR，回复与自己内容相关的评论。 |

具体人选由小组在组会上确定，并在仓库 Settings → Collaborators 中授予相应权限。建议负责人与备份维护者拥有 Admin 权限，其他成员拥有 Write 权限。

## 审阅一个 PR

每个 PR 需要一位作者以外的成员批准后才能合并。审阅时依次确认：

1. **自动检查通过**：PR 页面的 `Build docs and check examples` 显示为通过。未通过时，检查日志会指出出错的文件与字段。
2. **预览效果**：在检查结果页下载 `site-preview`，解压后用浏览器打开 `index.html`，查看新页面的排版、公式与链接。
3. **位置与元信息**：文件放在正确目录；`type`、`stage`、`tags` 与内容相符；论文的题名、作者、年份与原文一致。
4. **来源与证据**：关键结论附有来源并尽量定位到章节或图表；原文结论、复现观察、个人理解与待验证假设已区分。
5. **公开范围**：不包含未发表想法、内部实验细节、私人信息或凭据。

意见较小时可以直接在 PR 中提出修改建议；需要较大改动时选择 Request changes，并写明原因。

## 合并与发布

- 使用 PR 页面的 **Merge pull request** 合并。合并后 `Deploy documentation` 工作流会自动构建并发布网站，通常一分钟内生效。
- 合并前确认讨论已解决（仓库要求所有审阅对话标记为已解决）。
- 管理员可以绕过审阅要求强行合并，仅在紧急修复且无人可审阅时使用，并在 PR 中说明原因。

## 处理评论与讨论

- 每个页面底部的评论保存在仓库 [Discussions](https://github.com/YishuaiGeng/seu-llm-logical-reasoning/discussions) 中，页面作者负责回复与自己内容相关的评论。
- 评论指出明确错误时，由作者或栏目维护人提交修订 PR，并在评论中回复修订链接。
- 不当内容按[行为准则](../../CODE_OF_CONDUCT.md)处理，可在 Discussions 中隐藏或删除。

## 定期维护

| 频率 | 事项 |
| --- | --- |
| 每次组会后 | 轮值记录人提交组会记录；行动项同步到 Issues 并指定负责人。 |
| 每月 1 日 | `External link check` 自动检查外部链接，发现失效时自动创建 Issue，由栏目维护人修复或替换链接。 |
| 每月 | 检查候选论文清单：已完成精读的条目从清单中删除，新的推荐从 Discussions 中筛选补充，并核实题名、作者与年份。 |
| 每学期 | 回顾学习路线与主题划分，确认成员权限，清理已离组成员的写权限，并视情况发布新版本。 |

## 常见维护操作

### 新成员加入

1. 负责人在 Settings → Collaborators 中邀请成员，授予 Write 权限。
2. 请新成员阅读[新成员指南](../getting-started/README.md)与[贡献指南](../../CONTRIBUTING.md)，从一篇候选论文或一个小主题开始。

### 新增主题目录或学习阶段

在 `mkdocs.yml` 的 `extra.knowledge.topics`（主题目录）或 `extra.knowledge.stages`（学习阶段）中添加一项，写明 `id`、`title` 与 `summary`。主题目录的 `id` 必须与 `docs/notes/` 下的文件夹名一致。修改后提交 PR 即可，导航与索引会自动更新。

### 修改评论区分类

在 Discussions 中新建分类后，打开 [giscus 配置页](https://giscus.app/zh-CN) 获取分类 ID，更新 `mkdocs.yml` 中 `extra.giscus` 的 `category` 与 `category_id`。

### 发布版本

栏目结构或网站功能有较大变化时，由负责人发布版本：

1. 在 [CHANGELOG.md](../../CHANGELOG.md) 顶部记录新版本的主要变化。
2. 同步更新 `CITATION.cff` 中的 `version` 与 `date-released`。
3. 合并后在 GitHub 的 Releases 页面创建新版本，标签格式为 `vX.Y.Z`。

日常内容更新不需要发布版本，合并后即自动上线。
