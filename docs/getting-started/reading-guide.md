# 阅读与验证方法

一篇好的阅读笔记不只是摘要。它应让后来者看懂作者解决的问题、主张依赖的证据，以及哪些问题仍未解决。

## 先确定任务

记录输入、输出、可用信息和评测目标。论文中的“推理”可能指逻辑有效性、数学求解、多跳问答或规划，不能仅凭名称就把这些任务等同。

## 沿着四个问题阅读

| 问题 | 笔记里应留下什么 |
| --- | --- |
| 作者要解决什么？ | 具体问题、现有方法的限制、适用假设 |
| 方法为什么可能有效？ | 机制解释、关键设计与必要的中间步骤 |
| 哪些证据支持主张？ | 数据、基线、指标、消融、原文图表位置 |
| 证据支持到哪里？ | 泛化边界、潜在混淆、失败案例与未决问题 |

## 区分四种陈述

笔记中用四种标注区分陈述的来源。它们在网站上以不同颜色呈现，读者一眼就能看出哪些已经核实、哪些仍是设想。以下均为写法示例，不是真实阅读记录。

!!! claim "原文结论"
    注明论文位置，例如“第 4 节表 2”。原文结论不自动视为自己已经核实。

!!! reproduced "复现观察"
    提供代码版本、配置、输入和实测结果。未复现时明确写“未复现”。

!!! insight "个人理解"
    解释自己的推断，以及依据来自哪里。

!!! hypothesis "待验证假设"
    说明可以如何检验，不把设想写成实验事实。

写法：

```markdown
!!! claim "原文结论"
    作者报告……（第 4 节表 2）
```

四种类型的关键字分别是 `claim`、`reproduced`、`insight`、`hypothesis`，标题可以按需要改写。

## 对逻辑推理多检查一步

答案正确不一定说明推导有效；推导在形式上有效，也不代表前提在现实中为真。可以追问：是否存在前提全真但结论为假的反例？模型对无关信息或等价改写是否稳定？评分器能否检测推理中的无效步骤？

不同检查测量不同性质。一个小型真值表验证只适用于它形式化覆盖的命题，不能推及模型的全部推理能力。
