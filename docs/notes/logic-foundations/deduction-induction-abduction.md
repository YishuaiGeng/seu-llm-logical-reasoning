# 演绎、归纳与溯因

前置知识：[蕴涵、有效性与反例](implication-and-entailment.md)。

## 本文要回答的问题

论文和基准里的“推理”常常混合了不同类型。演绎给出必然性，归纳与溯因给出可废止的合理判断。评测一个模型之前，应先确定任务要求的是哪一种，否则“答对了”可能测量的并不是我们以为的能力。

## 演绎：结论必然成立

前提为真时，结论不可能为假。有效的演绎是**保真**的，但不扩充信息：结论已经隐含在前提中。

```derivation
所有人都会死
苏格拉底是人
--- 全称例示 + 肯定前件
苏格拉底会死
```

演绎是**单调**的：增加新前提不会使原来有效的结论失效。

## 归纳：从实例到一般

从观察到的实例概括出一般规律，或预测下一个实例。归纳是**扩充性**的，结论超出了前提所说的内容，因此前提全真时结论仍可能为假。

```derivation
观察到的天鹅 1 是白色的
……
观察到的天鹅 n 是白色的
--- !归纳概括
所有天鹅都是白色的
```

推导块中的“无效”仅指它在演绎意义上不保真，并不否定归纳本身的价值。归纳的质量取决于样本量、代表性与背景知识，通常用概率或置信程度表达，而不是“有效/无效”。

## 溯因：寻找最佳解释

已知一个观察，推测最能解释它的假设。溯因的形式与肯定后件相同，因此**在演绎意义上无效**：

```derivation
如果下过雨，地面会湿
地面湿了
--- !溯因
（推测）下过雨
```

它的价值在于生成候选假设，再由进一步证据检验。“洒水车刚经过”同样能解释地面湿；选择哪个解释，取决于简洁性、先验可能性和背景知识。

## 对比

| | 演绎 | 归纳 | 溯因 |
| --- | --- | --- | --- |
| 方向 | 一般 → 特殊（典型情况） | 特殊 → 一般 | 观察 → 解释 |
| 前提全真时 | 结论必然为真 | 结论可能为假 | 结论可能为假 |
| 新增信息后 | 结论保持（单调） | 可能被推翻 | 可能被推翻 |
| 评价标准 | 有效性、健全性 | 样本与统计强度 | 解释力、简洁性 |

“一般到特殊”只是典型情况：由两个特殊命题推出另一个特殊命题的演绎同样常见，分辨的关键是结论是否必然成立。

## 对大模型评测的启发

1. **先确认任务类型。** 如果任务要求演绎，模型用常识“猜”出合理答案并不等于完成了演绎；反过来，在溯因任务中要求形式有效性也不合适。
2. **演绎任务可以用反例检验。** 构造前提全真、结论为假的情形，或者用[求解器](../../tutorials/z3-validity.md)检查。
3. **注意隐含前提。** 模型常常引入题目没有给出的常识作为前提。如果基准要求只依据给定前提推理，这类答案即使结论正确，也应单独统计。
4. 一些逻辑推理数据集同时包含演绎与溯因形式的问题，例如 ProofWriter 的标题就包含“abductive statements”。使用数据集时，应按问题类型分别报告结果。

!!! insight "个人理解"
    很多“推理失败”其实是任务类型错配：模型在需要演绎的地方做了溯因，即从结论出发倒推一个看似合理的前提。按推理类型拆分错误，可能比只看总体准确率更有诊断价值。
